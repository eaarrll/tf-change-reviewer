(`fifo_throughput_scope` placeholder), and an in-place `aws_dynamodb_table` update calls `DescribeTable`
at plan time, so neither can be updated in a fixture. An attribute that references another resource's

match the referenced one, which shows up as a fake in-place diff; these scenarios build such values
from known parts instead.

These six were generated with a local copy of `gen-fixtures.ts` that (a) re-plans the before config
against the crafted state and copies the now-known values in until it plans clean, so references to
another resource's computed value (`subnet_id`, `redrive_policy`, a bucket `id`) match instead of
showing fake replacements, leaving out with `-target` any resource whose plan calls AWS (the DynamoDB
table) plus its dependents; (b) leaves `snapshot_identifier` empty in the crafted state. With the
script as it is, `subnet-cascade` and `renamed-without-moved` get dozens of fake replacements.
