# Research: prior art for Terraform plan review (late 2026)

Prior art as of 2026-11-24. "Which change needs my attention?" already has many answers. Commercial platforms ship LLM plan summaries: env0 (Jun 2025), Scalr (doc updated Feb 2026), Spacelift Saturnhead/Infra Assistant (Apr 2025 to Mar 2026), Terramate AI Mate (Jun 2025), Digger/OpenTaco (invite-only), Pulumi Neo code reviews (public preview from 2026-06-22) and HCP Terraform through third-party run tasks or MCP. Risk ranking also exists: Harness IaCM Blast Radius Agent scores each resource 1-10 and sorts by risk, and Overmind classifies risks High/Medium/Low and adds Signals scored -5 to +5 from change history. Dozens of small open-source 2026 tools classify plans as safe/dangerous, so a summary or a ranking alone is commodity.
What is still unbuilt is the full lineage, from replace_paths through the resource expression and var.X to the module-call input in the parent, then to the changed .tf line in the PR diff. The closest are: tfwhy (Jul 2026, 0 stars), which maps replace_paths and action_reason to the declaring HCL block file:line across one level of local modules; Checkov --repo-root-for-plan-enrichment, which maps resource-block-level findings to code; tfplan2md, which lists the attributes that forced a replacement; and Terramate, which detects changes per stack via git. None links module inputs or diff hunks, and none flags a replacement that this PR's diff does not explain.
No vendor publishes precision or recall, and none documents a reviewer-feedback loop on plan findings. The only public measurements are tiny OSS evals (16 PRs; 10 labelled plans). Overmind runs AI hypotheses that it then confirms or rules out, which is self-verification, not a measured metric.
Local check on Terraform v1.10.5 (findings 15-17): replace_triggered_by never appears in plan JSON, and the JSON has no source positions, so lineage needs HCL parsing. Sensitive variable values leak in plaintext through `variables` and `configuration` (constant_value/default), not only through before/after. In that check the human-readable plan omitted the '# forces replacement' annotation that grep-based tools rely on.

## Design implications

- Position on evidence, not summaries. Every ranked item should carry a clickable chain: resource address, replace_paths/action_reason, the resource attribute expression (file:line at head SHA), var.X, the module_calls.<m>.expressions.<input> line in the parent, and the PR diff hunk. LLM summaries and severity tiers are already commodity (env0, Scalr, Spacelift, Terramate, Harness, Overmind, dozens of OSS Actions).
- Build lineage from plan JSON (replace_paths, action_reason, configuration expression `references`, `module_calls.*.expressions`, `variables`, `relevant_attributes`, `resource_drift`) plus an HCL parser. Plan JSON has no source positions, and `replace_triggered_by` is absent from it (both verified on v1.10.5), so file:line and replace_by_triggers edges must come from parsing .tf files.
- Make 'not explained by this PR's diff' a first-class, highly ranked finding with a cause taxonomy:
- drift (resource_drift/relevant_attributes)
- deferred data reads (read_because_dependency_pending / read_because_config_unknown, e.g. a module-level depends_on)
- provider-forced replacement on an unchanged attribute (#36097)
- tainted / replace_by_request / replace_by_triggers
- provider or module version bumps (.terraform.lock.hcl, module source ref)
- tfvars/CI -var differences
- unapplied changes merged by others (codemochi incident)
- Group resource changes by root-cause input before ranking: one module input change can fan out to hundreds of resources (the 14-service PR). Rank root causes; show 'var.engine_version (modules/db) → 1 replacement + 1 replace_triggered_by replacement' rather than N rows.
- Never depend on the human-readable plan for replacement detection. Use JSON replace_paths/action_reason. Locally, the text plan omitted '# forces replacement' for a map attribute; `terraform show` historically lacked it (#27618). Handle unknown action_reason values gracefully, because the HashiCorp docs list is incomplete versus the source.
- Redaction must go beyond before_sensitive/after_sensitive masks. Scrub:
- `variables[*].value` and `configuration...variables[*].default` for sensitive variables
- `module_calls.*.expressions.*.constant_value` feeding sensitive child variables
- prior_state, planned_values (sensitive_values), output_changes and resource_drift
- the text plan
  Send Claude only the evidence subgraph, and add a test fixture that asserts the canary strings never leave the process.
- Treat precision/recall as the product's moat:
- per-finding reviewer verdicts captured in the PR (confirm / not material / wrong lineage), e.g. reactions or checkboxes in a sticky comment
- a '/tfcr missed <address>' command for false negatives
- optional post-apply incident linkage
- a seeded offline benchmark of synthetic PRs with known dangerous changes, including non-delete dangers like password rotation and scale-to-zero, run in CI
- published numbers; no competitor does this
- Have the Claude agent confirm or refute deterministic lineage edges with read-only tools. Reject any agent claim (address, attribute, line or number) not present in the deterministic facts, as plan-explainer does. Show where the agent upgraded or downgraded materiality and why, and log it for the feedback dataset.
- Avoid cry-wolf: weight stateful types, replace vs update, IAM/network exposure, cost delta (ingest Infracost JSON if present), whether the cause is in the diff, and routine-ness (prior PR history of the same attribute, as Overmind Signals and DeployCompare do). Keep harmless deletes (null_resource/terraform_data, log groups) low, and measure this.
- Fit existing workflows: run as a post-plan step beside Atlantis/Digger/Terrateam/tfcmt; accept Checkov/conftest/Infracost outputs as signals; keep the PR comment short (top N root causes with permalinks) under GitHub's 65,536-char limit, with the full report in the job summary/artifact; consider an HCP Terraform run-task adapter later.
